# Output Quality Bar

**Created:** 2026-10-02 · **Owner:** @ghassan · **Instrument:** `scripts/quality_suite.py` + `automation_miner.evaluation`

## Why a new bar

The August program (`docs/improvement/`) closed an *engineering* bar: tests, typing,
budgets, trust boundaries. It deliberately never ran a real provider. The one real
run on disk shows what that missed: the product's final output — the brief a
process owner reads — is not good enough.

- 6 of 7 drafts were filtered; the 1 published brief scored ICE 18.
- That brief contains **75 provenance hedges** ("inferred from S2: '…'; not
  explicitly stated") and **85 lint errors**; its steps were double-numbered and its
  validation criterion was a garbled template sentence.
- Real domain knowledge (ArbZG working-time limits) was treated as an ungrounded
  claim, so the engine punished exactly the expertise the original vision asked for.
- The shipped default budget (120k tokens) is below what a normal real run uses
  (~300k), so a default real run ends `budget_exhausted`.

## The vision this bar measures against

From the original spec (commit `3e166d2`, `docs/spec/01-SKILL.md` and sample AM-099; summarized in [`docs/VISION.md`](../VISION.md)): *walk into a
factory with a map and a highlighter* and come out with **specific, expert,
ambitious, ready-to-evaluate automation briefs** — honestly scored. The deterministic
verification layer exists to keep that output *honest*, not to make it timid.

So a high-quality result is: **concrete and insightful like a strong analyst, honest
about what is observed vs. known vs. assumed, and readable by an executive.**

## The bar

Measured on the three-case suite in `examples/` with **only cheap models**
(`deepseek/deepseek-v4-flash` on every role, judge included) and the **shipped
default budget**. All checks must pass on all cases in the same suite run.

### Judge calibration

A judge on the generator's own model family must not be trusted uncalibrated.
The 16 briefs of iteration 1 were graded by a stronger reference judge
(`anthropic/claude-sonnet-5.5`), then re-graded by the flash judge:

| Case | Reference overall / fabricated | Flash judge v1 (holistic) | Flash judge v2 (audit + bounded) |
|---|---|---|---|
| claims | 2.57 / 42 | 4.00 / 3 | 2.29 / 34 |
| strategy | 2.25 / 19 | 4.00 / 0 | 2.25 / 14 |
| oneliner | 2.00 / 26 | 2.40 / 15 | 2.00 / 43 |

v1 would have passed work the reference judge fails. v2 enumerates every
organization-specific claim in a separate audit call, derives honesty from the
audit in code, writes weaknesses before grades, and caps `overall` at honesty+1.
Its per-case means sit within 0.3 of the reference and every brief within one
point, so the thresholds below keep their meaning with the cheap judge.

| Case | Input | Expectation |
|---|---|---|
| `claims` | `examples/claims-intake/` — SOP, metrics CSV, interviews (rich, operational) | mode = operational, ≥ 4 published, publication rate ≥ 60% |
| `strategy` | `examples/hospital-strategy-memo.md` — board memo | mode = strategy, ≥ 3 published |
| `oneliner` | "Independent veterinary clinics in the Netherlands" | ≥ 3 published, all framed as Discovery Hypotheses |
| `dhl` | `examples/dhl-germany-domain.md` — the input of the first real run | ≥ 4 published, publication rate ≥ 60% (was 1/7) |
| `large` | ~89k tokens generated by `scripts/make_large_kb.py` (21 synthetic field-service files) | mode = operational, ≥ 4 published; exercises digestion and evidence selection |

### Q1 — Functionality (every case)
- Run completes with status `completed` under the shipped default budget; no
  `budget_exhausted`, no hard JSON failure.
- Wall clock ≤ 15 minutes per run.

### Q2 — Reader-facing hygiene (deterministic lint, every published brief)
- **0 lint errors**: no inline provenance hedging, no double numbering, no empty
  required section, no garbled template sentence, no trailing punctuation in the domain.

### Q3 — Independent judge (every case)
- Mean **overall ≥ 4.0 / 5** ("clearly good, I would forward it").
- Every dimension mean (specificity, insight, actionability, domain expertise,
  epistemic honesty, readability) **≥ 3.5**.
- No published brief with overall **< 3**.
- Honesty: **≤ 0.5 fabricated org-specific facts per brief** on average.
- Portfolio: diversity **≥ 4**, coverage **≥ 3**.

### Q4 — Engineering (unchanged from the August bar, still required)
- `make ci-check` green: ruff, pytest, mypy, contract check, build.
- Every behaviour change has a focused offline test.
- No pipeline module grows beyond a single responsibility; the run lifecycle,
  graph wiring, and stage logic are separable.

## Loop protocol

1. Run the suite → `quality-report.md`.
2. Read the failing checks *and* the judge's weaknesses; fix the root cause in the
   engine, never by tuning the judge or the fixtures.
3. Re-run the full suite. Log every iteration in `01-ITERATION-LOG.md`.
4. Stop only when one complete suite run passes every check.

## Honest limits

The judge is a calibrated proxy for a human process owner, not a substitute. The
fixtures are synthetic. A green bar means the engine reliably produces briefs a
strong reviewer would forward on these inputs; product-market evidence still needs
real users and real documents (see `docs/improvement/02-REAL-PROVIDER-TEST-PLAN.md`).
